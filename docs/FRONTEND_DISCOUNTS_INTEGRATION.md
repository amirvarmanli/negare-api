# Frontend Discounts Integration Guide

This project now supports a single coupon discount path during checkout. Frontend should always use the `/checkout/price-quote` and `/checkout/confirm` endpoints to show totals and redeem coupons. Do not apply any subscription or legacy discounts on the client.

## Coupon price quote (`POST /checkout/price-quote`)

- Send the current cart items (`productId`, `quantity`) and include the `couponCode` string when the user enters one.
- Always take the returned `subtotal`, `appliedDiscountAmount`, and `total` from the response so your UI matches the backend math.
- Display `appliedDiscountReason` as the human-friendly summary (e.g. `Coupon WELCOME10 applied: 15% off`).
- Store the `appliedDiscountSource` value (`COUPON` or `NONE`) to know whether a coupon was applied.
- Keep the entire `discountMetadata` object, it includes:
  - `couponId`, `couponCode`, `couponValueType`, `couponValue`, `discountAmount`, `discountReason` (the six required fields).
  - `appliedDiscountPercent`, `appliedDiscountAmount`, and `appliedDiscountReason`.
  - An empty `nonAppliedDiscounts` array (currently unused).

The response format looks like this:

```
{
  "items": [...],
  "subtotal": 200000,
  "appliedDiscountPercent": 10,
  "appliedDiscountAmount": 20000,
  "total": 180000,
  "appliedDiscountSource": "COUPON",
  "appliedDiscountCode": "WELCOME10",
  "appliedDiscountReason": "Coupon WELCOME10 applied: 10% off",
  "nonAppliedDiscounts": [],
  "discountMetadata": {
    "subtotal": 200000,
    "appliedDiscountSource": "COUPON",
    "appliedDiscountPercent": 10,
    "appliedDiscountAmount": 20000,
    "appliedDiscountCode": "WELCOME10",
    "appliedDiscountReason": "Coupon WELCOME10 applied: 10% off",
    "couponId": "coupon-1",
    "couponCode": "WELCOME10",
    "couponValueType": "PERCENT",
    "couponValue": 10,
    "discountAmount": 20000,
    "discountReason": "Coupon WELCOME10 applied: 10% off",
    "nonAppliedDiscounts": []
  }
}
```

## Confirming checkout (`POST /checkout/confirm`)

- Submit the same `items` array plus the same `couponCode` (when present) and a unique `requestId` generated by your client.
- `requestId` keeps the endpoint idempotent: repeated calls with the same `requestId` return the cached response without touching coupon usage counters again.
- On success, the response includes the same discount fields and the payment intent details needed for `/payments/gateway/init`.
- If you receive an error or non-200, re-run `/checkout/price-quote` with the same payload before retrying.
- The server will only call `discountsService.commitCouponRedemption` once per successful confirm, so the coupon usage counter never increases on repeated requests.

## Error handling

When a coupon is invalid, `/checkout/price-quote` and `/checkout/confirm` respond with `400` and a structured body:

```
{
  "code": "DISCOUNT_COUPON_EXPIRED",
  "message": "Coupon has expired.",
  "meta": {
    "code": "WELCOME10",
    "expiresAt": "2026-01-01T00:00:00.000Z"
  }
}
```

Handle these codes explicitly:

1. `DISCOUNT_COUPON_INVALID`: the code was not found or soft-deleted.
2. `DISCOUNT_COUPON_INACTIVE`: the coupon exists but is disabled.
3. `DISCOUNT_COUPON_EXPIRED`: the current time is past the coupon's `expiresAt`.
4. `DISCOUNT_COUPON_LIMIT_REACHED`: the coupon's global usage limit (`maxUsage`) has been exhausted.

Each error includes `meta.code`. The limit error additionally includes `meta.maxUsage` and `meta.usedCount`, while `DISCOUNT_COUPON_EXPIRED` includes `meta.expiresAt`.

## Admin coupon endpoints

The backend exposes a dedicated admin controller at `/admin/discount-coupons`:

- `POST /admin/discount-coupons` – create a coupon (`title`, `code`, `valueType`, `value`, optional `maxUsage`, `note`, `expiresAt`, `isActive`).
- `GET /admin/discount-coupons` – list coupons with pagination and filters (`page`, `limit`, `q`, `isActive`, `includeDeleted`).
- `GET /admin/discount-coupons/:id` – fetch a single coupon.
- `PATCH /admin/discount-coupons/:id` – update the same fields.
- `DELETE /admin/discount-coupons/:id` – soft-delete (sets `deletedAt` and `isActive=false`).

The API returns `couponId`, `code`, `valueType`, `value`, `maxUsage`, `usedCount`, `isActive`, `expiresAt`, `note`, `createdAt`, and `updatedAt` for each coupon.

## Suggested UI flow

1. User edits cart items or enters a coupon -> call `/checkout/price-quote` and render the totals.
2. Show `appliedDiscountReason` when a coupon was applied, and use `discountMetadata` to back your promos.
3. When the user is ready, submit the same payload plus a generated `requestId` to `/checkout/confirm`.
4. Use the returned `payment` object to continue with the payment gateway.
5. If the confirm request is retried, the cached response will be returned and the coupon usage counter will not increase again.
